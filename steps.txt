## 2. Objectif frontend

Construire une application web moderne, claire et responsive pour le module CampusServices.

L'application doit permettre :

- a l'etudiant de gerer ses livres, reservations et demandes administratives ;
- a l'administrateur de gerer les demandes administratives et les salles ;
- au bibliothecaire de gerer le catalogue et les emprunts ;
- a chaque role d'avoir son propre dashboard et sa propre navigation ;
- au frontend de communiquer avec le backend via JWT ;
- au frontend d'afficher clairement les succes, erreurs, chargements et restrictions d'acces.

## 3. Stack frontend recommandee

Utiliser une stack simple et adaptee au projet :

```txt
React
Vite
React Router
CSS classique avec variables CSS
Fetch API native
```

Dependances minimales a prevoir plus tard :

```txt
vite
react
react-dom
react-router-dom
```

Eviter d'ajouter trop de librairies au debut. Le projet est un MVP universitaire, donc il doit rester facile a comprendre, installer et presenter.

## 6. Regles API a respecter

Base backend :

```txt
http://localhost:8080/api
```

Toutes les reponses backend suivent majoritairement ce format :

```json
{
  "success": true,
  "message": "Operation successful",
  "data": {}
}
```

Les erreurs suivent ce format :

```json
{
  "success": false,
  "message": "Error message"
}
```

Le frontend doit toujours :

- lire `success` ;
- lire `message` ;
- lire `data` ;
- afficher `message` en cas d'erreur ;
- envoyer le JWT dans l'en-tete `Authorization` ;
- rediriger vers login si le token est absent ou invalide.

Header attendu par le backend :

```http
Authorization: Bearer <accessToken>
```

## 7. Services API a construire

### 7.1 `api.js`

Objectif : centraliser les appels HTTP.

Responsabilites :

- definir `API_BASE_URL` ;
- recuperer `accessToken` depuis `localStorage` ;
- ajouter automatiquement le header `Authorization` ;
- parser les reponses JSON ;
- normaliser les erreurs ;
- exposer des fonctions `get`, `post` ;
- gerer les erreurs reseau ;
- gerer le cas ou le backend renvoie `success: false`.

Attention : le backend actuel ne configure pas CORS. Si le frontend tourne sur Vite (`localhost:5173`) et le backend sur `localhost:8080`, il faudra probablement ajouter CORS cote backend plus tard.

### 7.2 `authService.js`

Endpoints :

```txt
POST /auth/login
GET /auth/me
```

Fonctions a prevoir :

- `login(email, password)` ;
- `getCurrentUser()` ;
- `logout()` ;
- `saveSession(accessToken, user)` ;
- `getStoredToken()` ;
- `getStoredUser()`.

Apres login, stocker :

```txt
accessToken
user
```

Le user contient selon le role :

```txt

adminId

fullName
email

filiere
valid
```

### 7.3 `bookService.js`

Fonctions a prevoir :

## 8. Authentification et autorisation

### 8.1 `AuthContext.jsx`

Responsabilites :

- stocker `user`, `accessToken`, `isAuthenticated`, `loading` ;
- charger la session depuis `localStorage` au demarrage ;
- exposer `login`, `logout`, `refreshCurrentUser` ;
- verifier le role de l'utilisateur ;
- permettre aux pages de savoir si l'etudiant est valide.

### 8.2 `ProtectedRoute.jsx`

Responsabilites :

- bloquer l'acces si non connecte ;
- bloquer l'acces si role incorrect ;
- rediriger vers `/login`, `/unauthorized` ou dashboard selon le cas ;
- eviter que l'admin voie les pages etudiant ;
- eviter que le bibliothecaire voie les pages admin ;
- eviter que l'etudiant voie les pages admin ou bibliothecaire.

### 8.3 Redirection apres login

Selon `user.role` :

```txt
STUDENT -> /student/dashboard
ADMIN -> /admin/dashboard
LIBRARIAN -> /librarian/dashboard
```

### 8.4 Etudiant non valide

Si `user.role === "STUDENT"` et `user.valid === false` :

- afficher un bandeau d'alerte sur le dashboard ;
- bloquer les actions d'emprunt, reservation et demande administrative ;
- laisser l'utilisateur voir les pages en lecture si utile ;
- afficher un message clair : `Votre compte etudiant n'est pas valide pour utiliser ce service.`

## 19. Points backend a surveiller pendant integration

Le frontend doit etre construit selon le backend reel, mais ces limites doivent etre notees :

- CORS probablement absent ;
- `GET /api/rooms` public alors que le contrat JWT dit protege ;
- pas d'endpoint dashboard ;
- pas d'endpoint admin pour toutes les reservations ;
- pas d'endpoint bibliothecaire pour tous les emprunts ;
- `my-reservations` ne retourne pas `roomName` ;
- `admin/requests` ne retourne pas `studentName` ;
- `my-borrowings` ne retourne pas `author` ;
- gestion salles incomplete par rapport au prompt initial ;
- gestion emprunts bibliothecaire incomplete par rapport au prompt initial.

Regle importante : ne pas inventer des endpoints cote frontend. Si une donnee manque, afficher une version degradee proprement ou noter la limitation.
